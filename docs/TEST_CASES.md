## Exploratory testing charters

**C1: Price integrity across the journey (60 min).**
Explore search → select → checkout → payment → confirmation → email/receipt with different routes, passenger counts,
currencies and promo codes, looking for any point where the price changes without explanation, rounds differently, or
differs between screens, API responses and the receipt. _Heuristics:_ follow one booking's price through every system
that touches it; try amounts with 3 decimals, 0, very large, and currencies without minor units (JPY).

**C2: Concurrency and retries (45 min).**
Explore what happens when the same action happens twice: double-click Purchase, back-and-resubmit, two browser tabs
booking the last seat, two agents editing one booking, a network drop after payment. Look for duplicate bookings,
duplicate charges, lost updates and confusing states. _Tools:_ two browser profiles, DevTools network throttling and
"offline", the API for the second actor.

**C3: Supplier failures and slowness (45 min).**
Using a supplier sandbox or proxy (e.g. mock the GDS response), explore timeouts, 5xx errors, empty availability, a
price change between search and book, and partial failures (flight booked, hotel fails). Look for what the customer
is told, whether they are charged, and whether support can see what happened.
